# TaskCarry

**為 AI 工具提供專案記憶與協作能力。**

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md)

[下載 TaskCarry](https://github.com/bryan123466/taskcarry/releases/tag/v0.2.0rc4) · [從操作手冊開始](docs/zh-TW/windows-example.md) · [瞭解架構](docs/zh-TW/architecture.md)

讓一個長期專案能夠跨越 AI 對話、工作區與暫停時段繼續推進。TaskCarry 儲存任務背景、選定的工作檔案、成果歷史與下一步，協助你回到上次停下的位置。

當一個專案開始超出單一對話的範圍，它就能派上用場：軟體與文件同時推進，研究專案拆成幾條工作線，或產品開發、營運與文書工作並行開展。你使用的 AI 工具協助完成工作，TaskCarry 為這些工作提供持久的本機記錄，以及彙整成果的方法。

**目前的完整操作範例使用 Codex。** 工具透過命令列與 MCP 提供同一套本機能力，為接入其他 AI 工具留下擴充基礎。每種宿主仍需要個別確認連線與工作流程。

## 已經有 Git 與專案指令，為什麼還需要 TaskCarry？

Git 儲存檔案歷史，AGENTS.md 等專案指令說明 AI 應該如何工作，交接摘要協助下一個對話進入狀態。TaskCarry 把這些既有工具與專案不斷變化的實際進度聯繫起來。

| 你已經在使用的工具 | 它解決什麼 | TaskCarry 補充什麼 |
|---|---|---|
| Git | 檔案版本、分支與修改歷史 | 成果屬於哪個任務、哪個階段已被接收、還有什麼需要繼續。 |
| AGENTS.md 與 Skills | 工作方法與角色說明 | 實際儲存、交付、彙入專案或暫停的工作記錄。 |
| 對話摘要 | 給人或下一個對話補充背景 | 可以持續更新、跨對話查閱的任務記錄與檔案位置。 |
| 手動交接 | 協調少量工作線 | 可檢查的接收計畫、實際操作記錄，以及中斷後已支援的接續方法。 |

一個對話中的短任務，既有工具可能已經足夠。當你需要反覆回答 **「上次停在哪裡？哪份成果是目前版本？什麼已經彙入專案？」** 時，TaskCarry 會更有幫助。

## 哪些內容能跟著專案保留下來？

| 能力 | 可以如何使用 |
|---|---|
| **專案記憶** | 在對話之外儲存任務目標、已記錄的決定、目前位置與下一步。 |
| **儲存暫停位置** | 保留選定且已儲存的檔案與接續說明，不必把尚未完成的任務標成結束。 |
| **多個工作區協作** | 並行任務各自在獨立目錄推進，再將準備好的成果彙入共同版本。 |
| **按階段交付** | 任務還在繼續時，也能貢獻一個有用階段，並記錄新舊階段之間的關係。 |
| **看清目前工作** | 分頁查看需要關注的目前事項，同時保留暫停任務與已完成歷史。 |
| **中斷後接續** | 核對記錄與實際效果，使用適用的既有恢復方法，補辦缺步，避免盲目重做。 |
| **素材位置記錄** | 記錄大型檔案在哪裡，以及指定備份是否相符，不必把所有檔案都放進 Git。 |

記憶來自你或 AI 助手明確接入的任務、說明、檔案與交付。TaskCarry 不會自動收集全部私人對話，也不會儲存編輯器中尚未寫入磁碟的內容。

## 人、AI 與工具如何配合？

![使用者決定方向，治理對話負責協調，專業工作區並行推進，TaskCarry 保留專案記錄](docs/assets/collaboration.zh-TW.svg)

**治理對話**負責專案協調。它使用宿主提供的 AI 能力理解已提供的工作資訊，複核目前狀態，並呼叫 TaskCarry 工具。專業對話在明確分配的工作區中推進自己的任務。

TaskCarry 儲存記錄並執行已支援的本機操作。你保留專案方向、優先順序、業務驗收與對外交付的決定權。工具不需要另設模型 API，也不訓練模型。

例如，軟體已經完成可用模組，實驗暫時暫停，文件還在起草。治理可以先接收軟體階段，再保留另外兩項任務的目前位置。儲存有用的進展，不需要把整個專案標成完成。

## 日常工作怎麼走？

![推進任務、儲存進度、交付穩定階段、彙入共同專案、更新選定工作區、繼續工作](docs/assets/governance-flow.zh-TW.svg)

1. **在任務對話中工作。** 在分配好的工作區推進實際任務。
2. **儲存有用的暫停位置。** 暫停時記錄目前位置與選定檔案。
3. **交出準備好的成果。** 指明穩定版本與它修改的檔案。
4. **彙入共同專案。** 治理對話檢查計畫，透過工具接收這個階段。
5. **根據共同進度繼續。** 更新需要這些業務成果的工作區，保全支援範圍內的本機工作，並處理具體衝突。

一個階段被接收，不代表整個任務已經結束；暫停任務也可以繼續暫停。新階段替代舊階段需要明確關係與相符的修改歷史，獨立成果不會因為出現更新的檔案就被丟棄。

## 從一個專案開始

在[發布頁面](https://github.com/bryan123466/taskcarry/releases/tag/v0.2.0rc4)下載 **taskcarry-0.2.0rc4-product.zip**，按照 [Windows 操作手冊](docs/zh-TW/windows-example.md)開始。

1. **建立專案目錄與治理對話。** 手冊提供具體目錄範例與可複製的安裝提示詞，填寫 **【專案名稱】**與 **【一句話介紹】**即可。
2. **接入既有工作，或增加任務工作區。** 可以繼續使用合適的原對話；需要並行時再建立獨立工作區，並填寫 **【這個對話實際負責的工作】**。
3. **請治理進行首次複核。** 它檢查已接入的專案，直接在目前治理對話中說明結果。之後正常工作，需要時再設定定時整理。

沒有另一個報告應用程式需要開啟。安裝接入的首次回饋，以及日常專案彙總，都是治理 AI 根據 TaskCarry 記錄與工具在對話中給出的；設定宿主自動化後，也可以定時進行這些複核。

使用前不需要學習核心、查看資料庫，或執行開發者測試。

<img src="docs/assets/workspace-sidebar-example.png" alt="治理對話與專業任務對話的組織範例" width="360">

這是一種組織範例，角色與對話數量由你決定。若幾個既有對話共用一個工作目錄，可以在那裡保留一個主要寫入者，再依手冊把需要並行的職責安排到獨立工作區。

## 從本機工作逐步擴充

- **定時協調：** 使用宿主的排程任務，讓治理複核已接入的工作並給出有用彙總。安裝 TaskCarry 本身不會建立排程任務。
- **私有 Git：** 設定自己的遠端儲存庫，儲存選定且已提交的成果。素材參照協助定位檔案，複製、備份與遠端同步仍是明確進行的操作。
- **其他 AI 工具：** CLI 與 MCP 圍繞同一個核心提供接入方式。目前具體上手路徑是 Codex；這不代表所有 MCP 用戶端、模型或 AI 平台都已驗證。
- **多電腦：** [手冊](docs/zh-TW/remote-and-multicomputer.md)說明獨立任務分支與單一整合電腦的做法。真實雙電腦流程尚未完成端到端驗證，建議本機流程建立後再評估採用。

TaskCarry 使用 Python 3.11+，Git 工作流需要 Git。專案狀態儲存在本機，工具包含安裝接入、任務交付、治理與恢復四類專案技能。每個治理範圍使用一份本機狀態與一條接收基線。安裝更新的是工具與技能；把已接收的業務成果更新到工作區，是另一項需要檢查計畫的操作。詳見[維護說明](docs/zh-TW/governance-maintenance.md)與[實際能力範圍](docs/RELEASE_BOUNDARIES.md)。
