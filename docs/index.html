Three states, three different claims三个状态，三种不同的结论

01 / CHECKPOINT

Work is saved工作已保存

Selected saved files and a next step can be resumed. No automatic delivery or business completion.

指定的已保存文件和下一步可以接续，不自动转成交付，也不代表业务完成。

02 / DELIVERY

A stage is offered阶段明确交付

A frozen Git delta has an explicit task and scope. Later worker edits do not change it.

冻结的 Git 变化具有明确任务和范围，不跟随后续工作区编辑变化。

03 / ACCEPTANCE

Effects are verified接收效果已验证

The local baseline includes the stage. Technical integration remains separate from business approval.

本地基线已包含该阶段；技术集成与业务批准仍分别判断。

A single workflow, several useful interfaces同一个工作流，不同的使用接口

CLI, MCP, and Skills use the same core. The AI interprets task relationships; scoped tools verify and execute their operations. A checkpoint can retain work without putting it in an acceptance queue.

CLI、MCP 与 Skills 使用同一内核。AI 理解任务关系，有限工具核验并执行操作。检查点可以保留工作，而不把它放入待接收队列。

One onboarding path一条清楚的接入路线

  1. Create the folders and install through the governance chat.先建目录，在治理聊天完成安装。
  2. Provide [Project name] and [One-sentence introduction]; governance determines initialization or continuation.填写【项目名称】和【一句话介绍】，由治理判断初始化或接续。
  3. For new specialists, provide [n: number of new chats] and [Actual work for each chat].需要新专业窗口时填写【n：新窗口数量】及【每个窗口实际负责的内容】。
  4. Connect governance MCP, with CLI fallback to the same engine.接入治理 MCP，CLI 作为同一内核的后备。
  5. Inventory current state before receiving explicit stable stages.先盘点当前状态，再接收明确稳定的阶段。
  6. Schedule against the actual registered workspace and task set.定时治理读取实际登记的工作区和任务。

Keep everyday work clear让日常工作状态清楚

  • Each task works in its assigned local workspace.每个任务在分配的本地工作区推进。
  • Paused work keeps a next step without repeated backlog reminders.暂停工作保留下一步，不重复成为积压提醒。
  • Frozen delivery stays separate from subsequent edits.冻结交付与后续编辑分别管理。
  • Baseline updates preserve local work or report a specific conflict.基线更新保全本地工作，或报告具体冲突。

Keep existing work continuous现有工作继续，不重新立项

Reuse suitable existing workspaces. If several chats share one directory, keep one main specialist writer there and continue other parallel responsibilities in separate workspaces and chats, preserving scoped WIP and history. Sequential subtasks do not require new chats.

合适的原工作区可以复用。多个旧窗口共用一个目录时，保留一个主要专业写入者，其余需要并行推进的职责在独立工作区和新窗口接续，按范围保全 WIP 与原历史。顺序推进的子任务不必另开窗口。

An empty CoGov directory does not establish that no previous work exists. Governance briefly checks unclear context before deciding the baseline. For an old chat: paste the summary prompt there, send its reply with the handoff prompt to governance, then paste governance’s return prompt back into that chat.

A complete inventory covers registered work, not every app chat. It records unfinished and paused work without automatically accepting it as completed output.

空 CoGov 不代表没有旧工作；治理先核对不明确的现场，再决定基线。旧窗接入：贴归纳提示词给旧窗，把回复连同转交提示词交给治理，再把治理生成的回贴提示词贴回原窗。

完整盘点覆盖已登记工作，不代表自动发现全部应用聊天；未完与暂停工作保留状态，不自动作为完成成果接收。
