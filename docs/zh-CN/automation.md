# 让定时治理保持聚焦

[English](../en/automation.md) · [繁體中文](../zh-TW/automation.md)

先在项目治理聊天中配置一个定时任务，复用手动治理所用的 AGCT 工具和 control 目录。AI 负责理解任务证据，工具负责精确计划、执行和记录本地操作。安装 AGCT 本身不会创建调度器，也不会再启动另一套 AI 服务。

## 从最小配置开始

| 任务 | 职责 | 起步建议 |
|---|---|---|
| 治理任务 | 接收明确交付，接续未完操作，说明当前进度与具体下一条件 | 每日两次，例如项目所选时区的 09:00、17:00 |
| 可选只读观察 | 核对当前记录与运行环境，发现新增故障、结果不一致或证据缺口 | 每日一次，安排在治理时段之后 |
| 独立采集任务 | 起步通常不需要，治理已经读取登记工作 | 有独立来源和实际需要时再增加 |

时段是示例，不是固定要求。一份 control 及其接收基线由一个治理写入者负责；观察者不写入，也不成为额外批准层。专业窗口继续独立工作，错过时段后不需要重放每一个完整旧周期。

## 在现有治理聊天中直接使用

先让治理按下面的运行说明手动执行一轮，检查实际效果、处理范围和剩余项。确认符合预期后，使用这段配置提示词：

> 请为本聊天已接入的项目创建持续回到本聊天的定时治理任务，每天 09:00 和 17:00 运行，显示实际采用的时区与保存后的计划。保持当前模型及权限。每轮使用下方运行说明，每天第一轮同时提供晨报。没有有意义变化、失败或需要我操作的事项时保持安静。不另建 control，不为其他项目启用自动化。

把以下内容保存为定时任务的运行说明：

```text
继续治理本聊天已明确接入的项目，使用已经安装的 AGCT 工具和原 control 目录。按 $agct-governance-reconcile 工作，具体失败按 $agct-experience-recovery 判断。项目方向和专业验收仍由原责任人决定。

先读 agenda 和必要的 status 细节。询问前复用已有任务、检查点、交付、材料及用户决定证据。若获准的宿主工具能读取已接入聊天，仅查看发生变化或存在具体缺口的必要信息；不可读取时说明覆盖范围，继续有记录支持的工作。不从文件变化直接推定已交付，不读无关聊天。

选择小批接收范围，通常使用 reconcile limit 20，并核对实际冻结计划。agenda 的一页不是执行范围。续办前先核对已经发生的效果，在已有授权内执行精确计划，保留未完操作和检查点。只有专业任务确实需要代码或成果依赖时才用 adopt 更新工作区；读取公共进度或更新 Skills 不要求合并业务分支。

按错误码、范围和当前证据判断经验是否适用。refresh_plan 只建议生成新计划。输入未变的冲突要解决具体条件，不循环重试。在获准开发范围内修改共享实现，将候选与已安装运行版分开验证；暂不可执行时保留具名下一条件。不嵌套启动完整治理，不靠修改宿主权限、账号或调度修复单项任务。

分别说明本计划结果与当前全部剩余事项，批次完成不代表项目完成。暂停任务和已确认保留决定不反复催办。在安全位置保存精确操作和下一步，结束前核对一次实际回执，不为了出报告重新全查历史。仅对有意义变化、失败或需要用户操作的事项通知；每天第一轮另附简明晨报。
```

Skills 使用正常安装位置；定时任务中应保存上述说明，不能只依赖先前一条临时聊天。通过宿主提供的调度工具创建，并检查实际保存定义；不手改原生调度文件，不把凭证写进提示词。

## 晨报和可选观察

晨报可包含六项：已接收阶段与基线、实际采用代码的工作区、未完技术项及条件、有意义的材料与备份决定、运行观察及覆盖范围、下一步与用户动作。只建议有意义的备份，复用已验证副本和已有保留决定。晨报描述出报时状态，后续完成另报。

报告的生成和送达由 AI 与宿主完成。AGCT 没有提供持久化的每日一次出报器、原生聊天采集器或自动提醒计数器。提醒次数等策略应按项目明确设置，沉默不产生授权。

需要观察者时，可另建获准的只读任务，使用以下说明：

```text
只读观察本项目的 AGCT status、agenda 和 doctor 结果。比较最新治理完成结果的明确范围、当前未完操作与运行证据。不要接收、采用、恢复、安装、改任务状态、启动其他代理或批准治理写入者。安装成功不能证明所有宿主进程已重新加载。发现新增不一致或需要行动的变化时，说明具体对象与证据；历史保留状态不变时不重复通知。观察不可用是覆盖缺口，不是失败或成功的证明。
```

## 验证真正使用的接入方式

核对保存后的聊天与项目、周期、时区、模型设置、工具和运行环境访问能力。CLI 成功不能证明 MCP 已接通或原生定时已成功触发。先验证手动提示词，再检查首次定时结果；访问本地文件的任务需要电脑和桌面应用可用。参见[官方定时任务文档](https://learn.chatgpt.com/docs/automations?surface=app)。

AGCT 限制本批接收工作数量，并支持已实现操作的中断接续；它不强制终止 AI 对话、任意外部命令，也没有多电脑协调锁。需要停止时使用宿主控制，保留事务记录。更多边界见[维护与安全接续](governance-maintenance.md)。
