# 快速了解：给出项目介绍，由治理接入

[Windows 完整流程](windows-example.md) · [总览与选项](operation-manual.md) · [English](../en/getting-started.md) · [繁體中文](../zh-TW/getting-started.md)

直接打开 [Windows 完整操作流程](windows-example.md)。它是安装与操作的主入口；本页只说明这条接入流程，不重复另一套命令或提示词。

## 准备目录和两项项目输入

首次初始化前建立 `CoGov`、`CoGov/control` 和 `CoGov/toolkit`，将产品直接解压到 `toolkit`，使其中直接包含 `START_HERE.md` 与 `packages/`。在 `control` 新建治理聊天，按主手册安装。

向治理提供：

- **项目名称：【请填写项目名称】**
- **一句话介绍：【请用一句话说明项目要做什么】**

正常流程需要 Python 3.11+ 和 Git。治理建立专用 `runtime` 并安装产品包；`control` 是普通治理目录，不是专业 Git 工作区。一套根目录只用于一个现实项目。

治理根据实际现场判断首次建立基线或接续已有工作，你不必选择路线。**空的 CoGov 不代表没有旧成果。** 信息不清楚时，治理先简要核对已有成果，或先让原窗口按主手册第 3.1 节归纳现场，避免把已有任务当成全新空项目。

## 按需要加入专业窗口

需要新窗口时填写**【n：新专业窗口数量】**，由治理新增 n 个独立工作区并接续已有编号，再由你新建聊天并选择对应目录。每个窗口填写**【请填入该对话窗需要实际负责的项目内容】**。并行职责按需分开，顺序推进的子任务不必另开窗口。

原窗口按同一流程接入：

1. 把主手册的归纳提示词贴到原窗口，让它回复真实目录、Git 归属、任务与未完状态。
2. 把这份回复**连同手册的转交提示词**一起发给治理。
3. 治理核对现场、登记工作区与任务，生成给原窗口的完整接续提示词。
4. 把该提示词贴回原窗口，保留原任务、历史与 WIP 继续工作。

合适的原工作区可以原地复用。多个旧窗口共用一处目录时，保留一个主要专业写入者；其他需要并行的职责经保全后在独立新工作区接续。工具不会自动扫描应用里的全部聊天。

## 接入后怎样运行

1. [治理 MCP](windows-example.md#mcp)直接调用工具；CLI 是同一内核的后备入口。
2. [首次完整盘点](windows-example.md#delivery)覆盖已登记任务和工作区的当前状态。已纳入基线、稳定待接收、未完检查点与暂停状态分别处理；全覆盖不等于接收所有未完成果。
3. [按需配置自动化](windows-example.md#automation)，由宿主定时唤醒治理，读取实际登记范围，不固定窗口数量。
4. 日常继续实际业务：暂停保留检查点，稳定阶段明确交付，治理接收后按需更新可更新的工作区。

已安装的项目读取当前状态接续，不重新初始化。可选的[私有 Git、备份和多电脑流程](remote-and-multicomputer.md)在需要时再配置；未启用的选项不是积压任务。
