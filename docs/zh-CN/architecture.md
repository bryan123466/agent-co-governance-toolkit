# 架构与工作流

[English](../en/architecture.md) · [首页](../../README.zh-CN.md)

Agent Co-Governance Toolkit 把持久项目状态保存在模型聊天之外。本地内核统一负责记录和变更，CLI、本地 MCP 与项目 Skills 将同一内核提供给用户和 Codex。

## 组件职责

| 组件 | 职责 |
|---|---|
| 内核与存储 | 任务、指定文件的不可变快照、材料、适用经验、事件与当前状态 |
| Git 集成 | 冻结交付校验、计划、本地基线接收、效果验证与工作区采用 |
| CLI | JSON 请求文件与可解析的结果封装 |
| MCP | 固定到一个项目的有类型工具，不另建执行内核 |
| Skills | 指导何时保存、交付、接收与检查故障，不授予额外权限 |
| 可选调度器 | 根据宿主实际能力触发现有工作流 |

持久状态位于指定项目的 `.agct` 目录。数据库和快照属于项目资料，不应提交到公开仓库或直接附在问题反馈中。不要编辑数据库来制造成功状态。

## 明确的工作边界

1. 工作者登记任务，在已登记的 Git 工作区推进。
2. 暂停或到达有意义的节点时，对精确指定的已保存文件记录检查点。覆盖范围内的 Git 快照分别保存 HEAD、暂存区、工作区字节与新文件。
3. 稳定阶段明确交付提交号、基准提交和实际变化路径。冻结交付不跟随工作区后续编辑变化。
4. 治理针对精确基线 HEAD 形成计划，执行时指定已保存的计划。前提改变时重新计划，而不是要求用户重新批准原业务目标。
5. 集成先核对实际 Git 效果再记录终态。中断后再次调用时，先核对已经发生的效果，再考虑缺失步骤。
6. 工作区采用使用独立计划，在能够保全当前本地工作的条件下更新。有冲突时报告对应工作区，不把它扩大成所有任务都失败。

技术接收不替代业务意义、合规或客户验收。

## 迭代与历史

独立阶段保持独立。累计阶段必须明确声明替代对象、属于同一任务、证明提交祖先关系并覆盖旧变更路径。时间更晚、版本号更高或文件名相近都不足以证明替代。

替代后历史继续保留，但不自动留在待接收队列。暂停或没有变化的工作仍是当前状态，不不断升级成积压；也不能仅因用户没有新指令而判定任务已放弃。

## 经验必须进入实际行动

经验规则包含错误编号、操作、受支持版本、可选任务范围、启用状态和受支持的恢复动作。文字相似不等于适用。本候选版只接受工具内建的有限恢复动作，不执行经验记录携带的任意终端脚本。

采用已知恢复仍要核对当前条件。失效、禁用、版本不支持或任务不匹配的规则不能授权操作。未知问题保留具体下一步，不能写完解释就改称已解决。

公共预防修正是另一个维护环节：用合成材料复现、修改共享实现、运行回归验证，再发布版本。仅保存经验不等于补丁已安装，也不证明模型一定会使用经验。

## 运行范围

本候选版支持单机本地运行，多个工作树代表并行任务线。它不实现跨主机分布式租约、共识、远程推送、部署或跨聊天调度。本地日志不能保证任意外部服务上的“恰好一次”效果。

Agent 不能通过改项目规则取得更多原生权限。模型来自用户的 Codex 环境，工具不训练模型，也不暗中要求第二套推理服务。
