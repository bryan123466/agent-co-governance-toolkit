# 工具怎样让项目持续推进

[English](../en/architecture.md) · [繁體中文](../zh-TW/architecture.md) · [首页](../../README.zh-CN.md)

多个 Codex 窗口一起工作时，各自需要知道下一步做什么，也需要保留之前的成果。Agent Co-Governance Toolkit 为它们提供共同的任务记录，由治理窗口把准备好的成果汇总起来。文件和进度保存在你的电脑上，项目不依赖某一个聊天记住全部历史。

## 谁来做什么

你决定方向、分配职责，并判断成果是否符合需要。专业窗口在各自登记的目录中推进任务；治理窗口利用 AI 理解任务记录与成果之间的关系，再调用工具保存状态、汇总阶段和更新工作区。

| 组成 | 对你的作用 |
|---|---|
| 任务记录 | 把目标、当前位置、有效决定、已保存进度和下一步放在一起。 |
| Git 工作区 | 为并行任务提供独立文件，并保留修改历史。 |
| 接收基线 | 保存已经汇总进公共项目的阶段成果。 |
| CLI 与 MCP | 通过两种入口调用同一套本地工具与记录。 |
| 项目技能 | 说明何时以及如何保存进度、交付阶段、处理已知问题。 |
| 可选宿主定时任务 | 在指定时间唤醒治理窗口，执行同一套工作流程。 |

## 从未完成工作走到下一阶段

1. **推进任务。** 专业窗口使用已登记的工作区和稳定的任务记录。
2. **保存一个有用的暂停位置。** 检查点记录选定的已保存文件，以及下次从哪里继续。在选定范围内，Git 检查点区分已提交版本、暂存修改、工作文件和新文件。
3. **交出准备好的阶段。** 专业窗口说明具体 Git 提交、起始提交和完整修改路径。该工作区后续的编辑不会悄悄改变这份交付。
4. **汇总进公共项目。** 治理根据当前接收基线形成计划，核对范围后执行；如果基线先发生变化，就根据实际情况重新计划。
5. **更新已经准备好的工作区。** 更新使用单独计划，并保全支持范围内的本地工作。正在写入或存在具体冲突的工作区保留自己的下一步，其他独立任务继续。
6. **接着工作。** 记录说明哪些已汇总、哪些仍在进行、下一步是什么。成果是否达到业务或专业要求，仍由你判断。

## 保留历史，不重复处理旧工作

暂停的任务保留原位置，没有变化的任务不会每轮都成为新增积压。旧阶段被新的累计阶段覆盖后，历史仍可追溯。替代前，工具要确认新阶段属于同一任务和登记工作区、沿用旧提交的历史，并包含旧阶段的修改路径。仅凭文件名或日期更新不能证明覆盖，独立成果仍分别保留。

某次操作中断后，治理先核对实际发生了什么，再决定如何继续。已有有效记录会复用，只补工具支持的缺失步骤，不因为没有收到回复就假定整件事失败。

## 在适用的地方复用经验

经验记录说明一个已知问题和可用的恢复动作。工具会检查问题编号、操作类型、适用版本、任务范围和启用状态；条件符合时，已有方法可以帮助处理同类问题。写下一段经验不会自动增加修复能力，工具也不会执行经验里夹带的任意脚本。

遇到陌生问题，治理说明具体障碍和下一步。要从根本上预防一类问题，仍需修改共享软件并验证后安装；记录经验本身不等于已经安装修正，也不能保证模型一定会选用它。

## 记录保存在什么地方

项目的 `.agct` 目录保存任务数据库、事件、经验记录和指定文件快照。应把它们作为项目资料妥善备份，不公开数据库，也不直接改库把未完成事项变成成功。

工具在单台电脑上本地运行，独立工作树支持任务并行。跨电脑工作需要按手册明确交接任务分支；工具不提供跨机锁、自动远端推送或部署，也不保证恢复任意外部服务上已经发生的操作。

AI 来自你使用的 Codex 环境。工具不训练模型，也不要求另配自己的模型 API。技能不会增加权限，Codex 工具连接和定时任务仍通过宿主支持的方式启用。详见[实际能力与使用范围](../RELEASE_BOUNDARIES.md)。
