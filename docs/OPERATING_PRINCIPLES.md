# Working together over time / 持续协作 / 持續協作

## English

The toolkit helps a project keep moving across working sessions. Professional chats advance their own tasks; governance brings ready results together and keeps the current position clear. These practices make that collaboration easier to follow.

- **Save enough to continue.** Keep the task goal, useful decisions, selected files, and next step. A paused task can stay paused without repeated reminders to finish it.
- **Use what is already known.** Check existing task records, file evidence, and delivery history before asking for the same information again. Chats still need to be explicitly connected; the tools do not discover every conversation.
- **Collect work in meaningful stages.** A task can contribute a useful result before all its work is finished. Keep independent results separate, and require evidence before treating a new stage as a replacement for an old one.
- **Check the effect before repeating an action.** After an interruption, inspect the files, Git changes, and saved operation records. Continue supported missing steps instead of restarting everything.
- **Reuse relevant experience.** A known recovery is useful when its conditions match. Experience notes cannot execute arbitrary code or add missing recovery functions.
- **Keep unaffected work moving.** A conflict in one workspace is a specific problem to resolve, not a reason to overwrite it or halt every independent task.
- **Confirm the connection you will use.** Installing the toolkit, connecting MCP, and creating a host schedule are separate actions. Confirm each through its actual result.

Review the selected receiving plan: its `limit` defaults to 20 and is at most 100, including selected unfinished receiving work. A completed batch does not mean the whole project is complete. The tools do not enforce a total AI-session time limit or automatically rotate through every batch. Upgrading or moving a project needs a deliberate handoff; saved history does not by itself migrate pending operations. An OS or Codex failure may require host support, while saved project work remains available. [Scheduled governance](en/automation.md) offers a single-writer template and an optional read-only observer.

## 简体中文

工具帮助项目在多次工作之间持续推进：专业窗口推进自己的任务，治理汇总准备好的成果，并把当前进度说明白。下面这些做法让协作更容易接续。

- **保存足够的接续信息。** 保留任务目标、重要决定、选定文件与下一步；暂停任务可以继续暂停，不反复催办结束。
- **先用已经知道的信息。** 询问前先核对任务记录、实际文件和交付历史。窗口仍需明确接入，工具不会自动发现所有聊天。
- **按有意义的阶段汇总。** 一项任务尚未全部完成，也可以交出有用成果。独立成果分别保留，新阶段是否替代旧阶段要有依据。
- **重复操作前先看实际结果。** 中断后核对文件、Git 变化和操作记录，继续工具支持的缺失步骤，不从头重做整件事。
- **复用确实适用的经验。** 已知恢复方法在条件符合时才适用；经验文字不能执行任意代码或增加尚不存在的修复功能。
- **让不受影响的工作继续。** 一个工作区冲突，就处理那个具体问题，不覆盖它，也不停止所有独立任务。
- **确认要使用的连接已生效。** 安装工具、接通 MCP、建立宿主定时任务分别完成，并各自核对实际结果。

接收前要检查本次选择的计划：`limit` 默认 20、最大 100，包含选中的未完接收工作。批次完成不等于项目完成；工具没有强制 AI 对话总时限，也不会自动轮转执行所有批次。升级或移动项目需要明确交接；保留历史不代表未完成操作已自动迁移。操作系统或 Codex 故障可能需要处理宿主环境，已保存的项目工作继续保留。[定时治理](zh-CN/automation.md)提供单一写入者和可选只读观察者模板。

## 繁體中文

工具協助專案在多次工作之間持續推進：專業視窗推進自己的任務，治理彙整準備好的成果，並將目前進度說明清楚。以下做法讓協作更容易接續。

- **儲存足夠的接續資訊。** 保留任務目標、重要決定、選定檔案與下一步；暫停任務可以繼續暫停，不反覆催辦結束。
- **先用已經知道的資訊。** 詢問前先核對任務記錄、實際檔案與交付歷史。視窗仍需明確接入，工具不會自動發現所有對話。
- **按有意義的階段彙整。** 一項任務尚未全部完成，也可以交出有用成果。獨立成果分別保留，新階段是否替代舊階段要有依據。
- **重複操作前先看實際結果。** 中斷後核對檔案、Git 變更與操作記錄，繼續工具支援的缺失步驟，不從頭重做整件事。
- **重用確實適用的經驗。** 已知恢復方法在條件符合時才適用；經驗文字不能執行任意程式碼或增加尚不存在的修復功能。
- **讓不受影響的工作繼續。** 一個工作區衝突，就處理那個具體問題，不覆蓋它，也不停止所有獨立任務。
- **確認要使用的連線已生效。** 安裝工具、接通 MCP、建立宿主定時任務分別完成，並各自核對實際結果。

接收前要檢查本次選擇的計畫：`limit` 預設 20、最大 100，包含選中的未完接收工作。批次完成不等於專案完成；工具沒有強制 AI 對話總時限，也不會自動輪替執行所有批次。升級或移動專案需要明確交接；保留歷史不代表未完成操作已自動遷移。作業系統或 Codex 故障可能需要處理宿主環境，已儲存的專案工作繼續保留。[定時治理](zh-TW/automation.md)提供單一寫入者與可選唯讀觀察者範本。
