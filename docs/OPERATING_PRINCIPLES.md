# Working with TaskCarry over time / 持续协作 / 持續協作

## English

TaskCarry helps a project keep moving across AI working sessions. Professional chats advance their own tasks; governance brings ready results together and keeps the current position clear. Its AI host interprets the work, and the local tools retain records and perform supported operations. These practices make collaboration easier to follow.

- **Save enough to continue.** Keep the task goal, useful decisions, selected files, and next step. A paused task can stay paused without repeated reminders to finish it.
- **Use what is already known.** Check existing task records, file evidence, and delivery history before asking for the same information again. Chats still need to be explicitly connected; the tools do not discover every conversation.
- **Collect work in meaningful stages.** A task can contribute a useful result before all its work is finished. Keep independent results separate, and require evidence before treating a new stage as a replacement for an old one.
- **Check the effect before repeating an action.** After an interruption, inspect the files, Git changes, and saved operation records. Continue supported missing steps instead of restarting everything.
- **Reuse relevant experience.** A known recovery is useful when its conditions match. Experience notes cannot execute arbitrary code or add missing recovery functions.
- **Keep unaffected work moving.** A conflict in one workspace is a specific problem to resolve, not a reason to overwrite it or halt every independent task.
- **Confirm the connection you will use.** Installing the toolkit, connecting MCP, and creating a host schedule are separate actions. Confirm each through its actual result.

Keep each review focused on a useful batch. The agenda and receiving plan expose what was selected and what remains; follow the [command reference](COMMANDS.md) for their separate limits and continuation options. Finishing one batch does not finish the project, and the tools do not impose an AI-session time limit or automatically execute every remaining batch.

Ask governance to report meaningful changes, completed actions, retained work, and concrete next steps in the current chat. The same approach works for the first review after onboarding and later scheduled reviews; no separate report application is required. [Scheduled governance](en/automation.md) provides a single-writer template and an optional read-only observer.

Keep package updates, persistent project records, shared progress, and business-file updates distinct. Updating tools or reading state does not merge workspaces. Before replacing a plan after an interruption, check the effects of existing operations and continue supported missing steps. Use a new plan when the old plan is invalid and no existing operation can safely continue. Moving a project needs an explicit handoff, and host failures may require host support. See [maintenance](en/governance-maintenance.md).

## 简体中文

TaskCarry 帮助项目在多次 AI 工作会话之间持续推进：专业聊天推进自己的任务，治理汇总准备好的成果，并把当前进度说明白。AI 宿主负责理解工作，本地工具保留记录并执行支持的操作。下面这些做法让协作更容易接续。

- **保存足够的接续信息。** 保留任务目标、重要决定、选定文件与下一步；暂停任务可以继续暂停，不反复催办结束。
- **先用已经知道的信息。** 询问前先核对任务记录、实际文件和交付历史。窗口仍需明确接入，工具不会自动发现所有聊天。
- **按有意义的阶段汇总。** 一项任务尚未全部完成，也可以交出有用成果。独立成果分别保留，新阶段是否替代旧阶段要有依据。
- **重复操作前先看实际结果。** 中断后核对文件、Git 变化和操作记录，继续工具支持的缺失步骤，不从头重做整件事。
- **复用确实适用的经验。** 已知恢复方法在条件符合时才适用；经验文字不能执行任意代码或增加尚不存在的修复功能。
- **让不受影响的工作继续。** 一个工作区冲突，就处理那个具体问题，不覆盖它，也不停止所有独立任务。
- **确认要使用的连接已生效。** 安装工具、接通 MCP、建立宿主定时任务分别完成，并各自核对实际结果。

每轮围绕一个有意义的批次推进。当前事项清单与接收计划会说明本次选择和剩余内容，各自的限制与接续方式见[命令参考](COMMANDS.md)。一个批次完成不代表整个项目完成；工具不强制 AI 对话总时限，也不会自动执行全部剩余批次。

请治理在当前聊天中说明有意义的变化、已完成操作、保留工作与明确下一步。安装接入后的首次复核和后续定时复核都使用这种方式，不需要独立报告应用。[定时治理](zh-CN/automation.md)提供单一写入者和可选只读观察者模板。

分别管理安装包更新、持久项目记录、共享进度和业务文件更新。更新工具或读取状态不会合并工作区。中断后替换计划前，先核对既有操作效果并接续支持的缺步；原计划失效且没有可安全接续的既有操作时，再重新计划。移动项目需要明确交接，宿主故障可能需要处理宿主环境。详见[维护说明](zh-CN/governance-maintenance.md)。

## 繁體中文

TaskCarry 協助專案在多次 AI 工作對話之間持續推進：專業對話推進自己的任務，治理彙整準備好的成果，並將目前進度說明清楚。AI 宿主負責理解工作，本機工具保留記錄並執行支援的操作。以下做法讓協作更容易接續。

- **儲存足夠的接續資訊。** 保留任務目標、重要決定、選定檔案與下一步；暫停任務可以繼續暫停，不反覆催辦結束。
- **先用已經知道的資訊。** 詢問前先核對任務記錄、實際檔案與交付歷史。視窗仍需明確接入，工具不會自動發現所有對話。
- **按有意義的階段彙整。** 一項任務尚未全部完成，也可以交出有用成果。獨立成果分別保留，新階段是否替代舊階段要有依據。
- **重複操作前先看實際結果。** 中斷後核對檔案、Git 變更與操作記錄，繼續工具支援的缺失步驟，不從頭重做整件事。
- **重用確實適用的經驗。** 已知恢復方法在條件符合時才適用；經驗文字不能執行任意程式碼或增加尚不存在的修復功能。
- **讓不受影響的工作繼續。** 一個工作區衝突，就處理那個具體問題，不覆蓋它，也不停止所有獨立任務。
- **確認要使用的連線已生效。** 安裝工具、接通 MCP、建立宿主定時任務分別完成，並各自核對實際結果。

每輪圍繞一個有意義的批次推進。目前事項清單與接收計畫會說明本次選擇與剩餘內容，各自的限制與接續方式見[指令參考](COMMANDS.md)。一個批次完成不代表整個專案完成；工具不強制 AI 對話總時限，也不會自動執行全部剩餘批次。

請治理在目前對話中說明有意義的變化、已完成操作、保留工作與明確下一步。安裝接入後的首次複核與後續定時複核都使用這種方式，不需要獨立報告應用程式。[定時治理](zh-TW/automation.md)提供單一寫入者與可選唯讀觀察者範本。

分別管理安裝套件更新、持久專案記錄、共用進度與業務檔案更新。更新工具或讀取狀態不會合併工作區。中斷後替換計畫前，先核對既有操作效果並接續支援的缺步；原計畫失效且沒有可安全接續的既有操作時，再重新計畫。移動專案需要明確交接，宿主故障可能需要處理宿主環境。詳見[維護說明](zh-TW/governance-maintenance.md)。
