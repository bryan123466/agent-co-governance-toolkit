# 用一个示例项目了解 TaskCarry

[English](TESTER_START.md) · [操作手册](zh-CN/windows-example.md)

接入实际项目时，推荐直接按照[操作手册](zh-CN/windows-example.md)进行。如果想先看看工作流程，可以选择下面这个可选示例，在独立目录使用虚构文件体验。你不需要提供私有材料，也不需要成为软件测试人员。

在[发布页面](https://github.com/bryan123466/taskcarry/releases/tag/v0.2.0rc5)下载 **taskcarry-0.2.0rc5-product.zip**，把解压后的产品包和一个新示例目录交给 Codex 聊天。

## 可以直接使用的提示词

> 请阅读这份 TaskCarry 产品包中的 README.zh-CN.md 和 docs/zh-CN/windows-example.md，帮助我在 **【新建的示例目录】** 中了解工作流程。只使用虚构材料，不改变已有项目和用户级配置。
>
> 按照手册准备治理目录和独立 Python 环境，核对产品版本，说明实际安装了什么。建立一个小型虚构项目，包含两个任务工作区和一条接收基线。
>
> 在一个工作区保存尚未完成任务的检查点和接续说明；在另一个工作区准备并交付一个有用阶段，检查接收计划后汇入共同项目。说明暂停任务如何继续保留，而不会变成新增交付义务。需要时可以再演示一个明确关联前阶段的累计版本。
>
> 直接在当前聊天中说明项目现状与下一步，区分实际保存、已经接收和仍处于计划中的内容。再次检查已完成的接收时复用已有结果。如果演示工作区更新或检查点恢复，先检查计划并保留已有文件；恢复只进入新目录。
>
> 先使用可用的 CLI。如果我要使用 MCP，且本宿主支持，请说明需要的配置，在完成必要宿主确认后实际调用工具验证。分别说明本地命令成功与真实宿主连接情况。不创建定时任务、不推送远端、不部署、不读取其他项目文件。

## 你会看到什么

这个聊天会说明任务记录与示例文件保存在哪里、哪个阶段已经汇入项目，以及未完成任务如何继续。TaskCarry 不会另开报告应用；日常项目汇总由治理 AI 根据工具和记录在聊天中形成，定时整理则通过可选的宿主设置完成。

如果采用表单示例，表单只是虚构的文档成果，不是对多个 AI Agent 能力的品质评分；也可以换成其他小型示例。

愿意反馈时，可以说明哪个步骤有帮助或不好理解，使用[脱敏问题模板](../templates/defect-report.md)即可。这不是使用产品的前提。故障注入和开发回归验证只应在可丢弃的虚构测试项目中进行，不在实际工作项目里尝试。
