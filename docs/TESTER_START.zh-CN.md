# 首轮试用：从一个虚构项目开始

[English](TESTER_START.md) · [完整试用指南](zh-CN/trial-guide.md) · [验证记录](VALIDATION.md)

本轮目标是验证别人能否独立安装、理解状态并完成一个小型工作流。请使用源码 ZIP、同版本 wheel 和 SHA256SUMS.txt；不需要提供真实项目材料。

## 可以直接交给 Codex 的提示词

> 请先阅读这份 Agent Co-Governance Toolkit 的 README.zh-CN.md、docs/VALIDATION.md 和 docs/zh-CN/trial-guide.md。
> 在我指定的新建临时目录中创建独立 Python 虚拟环境，优先从同版本 wheel 安装，不使用管理员权限，不改变其他项目。
> 使用包内的虚构品质表单示例进行试用：创建任务与三个工作区；先保存一个未完成工作的检查点；交付一个稳定阶段，再交付明确覆盖前一阶段的累计版本；将当前阶段接收到专用基线；在工作者保留暂存、未暂存和新文件的情况下采用基线。
> 核对已经完成的交付不会再次执行，暂停工作不会被当成新积压；恢复检查点必须进入新的独立目录。使用 CLI 完成这些验证后，再预览项目 Skills 和 MCP 配置片段。只有本机支持且我确认配置位置后才启用 MCP，然后实际调用 agct_doctor 与 agct_status。
> 分别报告 CLI、Git、MCP 协议、Codex 实际连接是否成功。遇到错误先保留原始现场与已发生效果，不用 reset、clean 或修改数据库强迫通过；不运行自动化、不推送、不部署、不读取或上传其他项目材料。按 templates/defect-report.md 给出简短反馈。

## 本轮希望收到的反馈

| 检查点 | 合格结果 |
|---|---|
| 安装 | 在独立环境运行帮助和 doctor，版本正确。 |
| 当前状态 | 能分清任务暂停、阶段交付、技术接收。 |
| 迭代 | 明确累计后继被接收，旧候选留痕且不重复执行。 |
| 保全 | 本地提交、index、未暂存与新文件没有丢失或混入交付。 |
| 重试 | 已接收结果被复用，没有重复集成提交。 |
| Codex 接入 | 分别记录“未启用”“宿主启动失败”或“已实际调用”，不要仅凭生成 TOML 判定成功。 |
| 使用体验 | 最困惑的一步、报错是否给出下一步、需要手工填写的内容。 |

故障注入由独立测试套件创建自己的可丢弃仓库。不要对自己的工作项目设置测试标记或注入故障。提交反馈时只包含虚构复现和必要错误，不上传整个治理状态目录。

如果只想先测试安装与基本流程，可先不启用 MCP；这属于工具试用通过，不能记为 Codex 集成验收通过。
