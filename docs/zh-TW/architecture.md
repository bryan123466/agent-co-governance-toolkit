# 工具如何讓專案持續推進

[English](../en/architecture.md) · [简体中文](../zh-CN/architecture.md) · [首頁](../../README.zh-TW.md)

多個 Codex 視窗一起工作時，各自需要知道下一步做什麼，也需要保留先前的成果。Agent Co-Governance Toolkit 為它們提供共同的任務記錄，由治理視窗把準備好的成果彙整起來。檔案與進度儲存在你的電腦上，專案不依賴某一個對話記住全部歷史。

## 誰來做什麼

你決定方向、分配職責，並判斷成果是否符合需要。專業視窗在各自登記的目錄中推進任務；治理視窗利用 AI 理解任務記錄與成果之間的關係，再呼叫工具儲存狀態、彙整階段與更新工作區。

| 組成 | 對你的作用 |
|---|---|
| 任務記錄 | 把目標、目前位置、有效決定、已儲存進度與下一步放在一起。 |
| Git 工作區 | 為並行任務提供獨立檔案，並保留修改歷史。 |
| 接收基線 | 儲存已經彙整進共用專案的階段成果。 |
| CLI 與 MCP | 透過兩種入口呼叫同一套本機工具與記錄。 |
| 專案技能 | 說明何時以及如何儲存進度、交付階段、處理已知問題。 |
| 可選宿主定時任務 | 在指定時間喚醒治理視窗，執行同一套工作流程。 |

## 從未完成工作走到下一階段

1. **推進任務。** 專業視窗使用已登記的工作區與穩定的任務記錄。
2. **儲存一個有用的暫停位置。** 檢查點記錄選定且已儲存的檔案，以及下次從哪裡繼續。在選定範圍內，Git 檢查點區分已提交版本、暫存修改、工作檔案與新檔案。
3. **交出準備好的階段。** 專業視窗說明具體 Git 提交、起始提交與完整修改路徑。該工作區後續的編輯不會悄悄改變這份交付。
4. **彙整進共用專案。** 治理依照目前接收基線形成計畫，核對範圍後執行；如果基線先發生變化，就依實際情況重新計畫。
5. **更新已經準備好的工作區。** 更新使用獨立計畫，並保全支援範圍內的本機工作。正在寫入或存在具體衝突的工作區保留自己的下一步，其他獨立任務繼續。
6. **接著工作。** 記錄說明哪些已彙整、哪些仍在進行、下一步是什麼。成果是否達到業務或專業要求，仍由你判斷。

## 保留歷史，不重複處理舊工作

暫停的任務保留原位置，沒有變化的任務不會每輪都成為新增積壓。舊階段被新的累積階段涵蓋後，歷史仍可追溯。替代前，工具要確認新階段屬於同一任務和登記工作區、沿用舊提交的歷史，並包含舊階段的修改路徑。僅憑檔名或日期更新不能證明涵蓋，獨立成果仍分別保留。

某次操作中斷後，治理先核對實際發生了什麼，再決定如何繼續。已有有效記錄會重用，只補工具支援的缺失步驟，不因為沒有收到回覆就假定整件事失敗。

## 在適用的地方重用經驗

經驗記錄說明一個已知問題與可用的恢復動作。工具會檢查問題編號、操作類型、適用版本、任務範圍與啟用狀態；條件符合時，已有方法可以協助處理同類問題。寫下一段經驗不會自動增加修復能力，工具也不會執行經驗裡夾帶的任意指令碼。

遇到陌生問題，治理說明具體障礙與下一步。要從根本上預防一類問題，仍需修改共用軟體並驗證後安裝；記錄經驗本身不等於已經安裝修正，也不能保證模型一定會選用它。

## 記錄儲存在什麼地方

專案的 `.agct` 目錄儲存任務資料庫、事件、經驗記錄與指定檔案快照。應將它們作為專案資料妥善備份，不公開資料庫，也不直接改庫將未完成事項變成成功。

工具在單台電腦上本機執行，獨立工作樹支援任務並行。跨電腦工作需要依手冊明確交接任務分支；工具不提供跨機鎖、自動遠端推送或部署，也不保證恢復任意外部服務上已經發生的操作。

AI 來自你使用的 Codex 環境。工具不訓練模型，也不要求另設自己的模型 API。技能不會增加權限，Codex 工具連線與定時任務仍透過宿主支援的方式啟用。詳見[實際能力與使用範圍](../RELEASE_BOUNDARIES.md)。
