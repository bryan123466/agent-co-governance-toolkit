# 架構與工作流程

[English](../en/architecture.md) · [简体中文](../zh-CN/architecture.md) · [首頁](../../README.zh-TW.md)

Agent Co-Governance Toolkit 把持久專案狀態儲存在模型對話之外。本機核心統一負責記錄和變更，CLI、本機 MCP 與專案 Skills 將同一核心提供給使用者和 Codex。

## 元件職責

| 元件 | 職責 |
|---|---|
| 核心與儲存 | 任務、指定檔案的不可變快照、材料、適用經驗、事件與當前狀態 |
| Git 整合 | 凍結交付校驗、計畫、本機基線接收、效果驗證與工作區採用 |
| CLI | JSON 請求檔案與可解析的結果封裝 |
| MCP | 固定到一個專案的具有型別定義的工具，不另建執行核心 |
| Skills | 指導何時儲存、交付、接收與檢查故障，不授予額外權限 |
| 可選排程器 | 根據宿主實際能力觸發現有工作流程 |

持久狀態位於指定專案的 `.agct` 目錄。資料庫和快照屬於專案資料，不應提交到公開儲存庫或直接附在問題回饋中。不要編輯資料庫來製造成功狀態。

## 明確的工作邊界

1. 工作者登記任務，在已登記的 Git 工作區推進。
2. 暫停或到達有意義的節點時，對精確指定的已儲存檔案記錄檢查點。覆蓋範圍內的 Git 快照分別儲存 HEAD、暫存區、工作區位元組與新檔案。
3. 穩定階段明確交付提交號、基準提交和實際變化路徑。凍結交付不跟隨工作區後續編輯變化。
4. 治理針對精確基線 HEAD 形成計畫，執行時指定已儲存的計畫。前提改變時重新計畫，而不是要求使用者重新批准原業務目標。
5. 整合先核對實際 Git 效果再記錄終態。中斷後再次呼叫時，先核對已經發生的效果，再考慮缺失步驟。
6. 工作區採用使用獨立計畫，在能夠保全當前本機工作的條件下更新。有衝突時報告對應工作區，不把它擴大成所有任務都失敗。

技術接收不替代業務意義、合規或客戶驗收。

## 迭代與歷史

獨立階段保持獨立。累積階段必須明確宣告替代對象、屬於同一任務、證明提交祖先關係並覆蓋舊變更路徑。時間更晚、版本號更高或檔案名相近都不足以證明替代。

替代後歷史繼續保留，但不自動留在待接收隊列。暫停或沒有變化的工作仍是當前狀態，不會不斷升級成積壓；也不能僅因使用者沒有新指令而判定任務已放棄。

## 經驗必須進入實際行動

經驗規則包含錯誤編號、操作、受支援版本、可選任務範圍、啟用狀態和受支援的恢復動作。文字相似不等於適用。本候選版只接受工具內建的有限恢復動作，不執行經驗記錄攜帶的任意終端機指令碼。

採用已知恢復仍要核對當前條件。失效、禁用、版本不支援或任務不匹配的規則不能授權操作。未知問題保留具體下一步，不能寫完解釋就改稱已解決。

公共預防修正是另一個維護環節：用合成材料重現、修改共用實作、執行回歸驗證，再發布版本。僅儲存經驗不等於修補程式已安裝，也不證明模型一定會使用經驗。

## 執行範圍

本候選版支援單機執行，多個工作樹代表並行任務線。它不實現跨主機分散式租約、共識、遠端推送、部署或跨對話排程。本機日誌不能保證任意外部服務上的“恰好一次”效果。

Agent 不能通過改專案規則取得更多原生權限。模型來自使用者的 Codex 環境，工具不訓練模型，也不暗中要求第二套推理服務。
