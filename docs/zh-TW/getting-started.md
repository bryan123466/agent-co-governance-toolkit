# 開始使用：把專案進度和工作視窗接起來

[Windows 完整流程](windows-example.md) · [總覽與選項](operation-manual.md) · [English](../en/getting-started.md) · [简体中文](../zh-CN/getting-started.md)

你可以繼續使用原有本機 AI 工作視窗，也可以為需要並行的工作增加獨立視窗。治理根據你提供的任務與檔案資訊整理進度、彙整階段成果。具體操作手冊以 Codex 為例；其他宿主需分別核驗 CLI/MCP 連線與指令載入方式。

先依照 [Windows 完整操作流程](windows-example.md)安裝；其中提供可直接複製的提示詞與指令。本頁幫助你瞭解安裝後會如何工作。

## 準備目錄和兩項專案輸入

首次初始化前建立 `TaskCarry`、`TaskCarry/control` 和 `TaskCarry/toolkit`，將產品直接解壓到 `toolkit`，使其中直接包含 `START_HERE.md` 與 `packages/`。在 `control` 建立治理對話，按主手冊安裝。

向治理提供：

- **專案名稱：【請填寫專案名稱】**
- **一句話介紹：【請用一句話說明專案要做什麼】**

正常流程需要 Python 3.11+ 和 Git。治理建立專用 `runtime` 並安裝產品套件；`control` 是普通治理目錄，不是專業 Git 工作區。一套根目錄只用於一個現實專案。

治理根據實際現場判斷首次建立基線或接續已有工作，你不必選擇路線。**空的 TaskCarry 不代表沒有舊成果。** 資訊不清楚時，治理先簡要核對已有成果，或先讓原視窗按主手冊第 3.1 節歸納現場，避免把已有任務當成全新空專案。

## 按需要加入專業視窗

需要新視窗時填寫**【n：新專業視窗數量】**，由治理新增 n 個獨立工作區並接續已有編號，再由你建立對話並選擇對應目錄。每個視窗填寫**【請填入該對話窗需要實際負責的專案內容】**。並行職責按需分開，順序推進的子任務不必另開視窗。

原視窗按同一流程接入：

1. 把主手冊的歸納提示詞貼到原視窗，讓它回覆真實目錄、Git 歸屬、任務與未完狀態。
2. 把這份回覆**連同手冊的轉交提示詞**一起發給治理。
3. 治理核對現場、登記工作區與任務，生成給原視窗的完整接續提示詞。
4. 把該提示詞貼回原視窗，保留原任務、歷史與 WIP 繼續工作。

合適的原工作區可以原地重用。多個舊視窗共用一處目錄時，保留一個主要專業寫入者；其他需要並行的職責經保全後在獨立新工作區接續。工具不會自動掃描應用裡的全部對話。

## 接入後怎樣執行

1. [治理 MCP](windows-example.md#mcp)直接呼叫工具；CLI 是同一核心的後備入口。
2. 在目前對話[執行首次有限治理](windows-example.md#delivery)，直接看到安裝、連線、已接入工作、本輪實際結果與你的下一步。沒有交付時說明已就緒，不建立示範工作；未完成任務繼續保留進度與下一步。
3. [按需設定自動化](windows-example.md#automation)，重用首次治理結果，不重複試跑；由宿主定時喚醒治理，使用同一 Skill 與工具，日常結果繼續在對話中回報。
4. 日常繼續實際工作。暫停時儲存需要保留的檔案與下一步；完成一個穩定階段後交給治理彙整，再依需要更新可以安全更新的工作區。工具將這種儲存進度的記錄稱為「檢查點」。

歷史記錄和暫停位置會保留。再次開啟已安裝的專案時，讀取目前狀態接續，不重新初始化。可選的[私有 Git、備份和多電腦流程](remote-and-multicomputer.md)在需要時再設定；未啟用的選項不是積壓任務。
