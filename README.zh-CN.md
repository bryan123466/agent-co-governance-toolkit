# Agent Co-Governance Toolkit

**让 AI 协作拥有连续的项目记忆，让多个工作台共同推进一个长期项目。**

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md)

[下载与安装](https://github.com/bryan123466/agent-co-governance-toolkit/releases) · [操作手册](docs/zh-CN/windows-example.md) · [架构说明](docs/zh-CN/architecture.md)

Agent Co-Governance Toolkit（AGCT）是一套面向 **Codex 用户**的开源项目协作工具。它将分散在不同工作台的任务进度、阶段成果、重要决定与接续信息，组织成可保存、可追溯、可继续使用的项目记录。

你可以让不同的 Codex 聊天分别推进软件、硬件、算法、科研、运营或文书工作，再由一个治理聊天结合 AI 与工具，汇总进度、接收成果，并在合适的时候把共同成果更新到各个工作区。已有聊天可以接入，正在进行的工作可以继续。

**它适合已经在使用 Codex，希望把多个对话组织成长期项目的人。** 你负责项目方向与重要决定，Codex 负责理解和推进工作，AGCT 负责让这些工作的状态与成果有据可查。

## 为什么需要 AGCT？

一段对话可以完成一个任务，但长期项目往往会跨越许多对话、文件和版本。工作逐渐增多后，真正费力的事情变成了：

- 隔了一周回来，要重新解释做到哪里、为什么这么做、下一步是什么。
- 几个聊天都在推进，却很难看清哪些成果已经汇入项目，哪些还在各自的工作区。
- 同一任务迭代了多个版本，旧记录和当前待办混在一起。
- 某次操作中断后，不确定哪些已经完成，是否需要从头再来。

AGCT 在日常工作中保存这些关系。**项目进度不必只靠聊天上下文维持；各自独立的工作，也可以汇成一份清楚的整体状态。**

## 你可以用它做什么？

| 能力 | 对你的工作有什么帮助 |
|---|---|
| **长期项目记忆** | 持久保存已登记任务的进度、关键决定、成果位置与下一步，方便跨会话接续。 |
| **多个工作台协作** | 为需要并行的任务准备独立工作区，让不同专业聊天各自推进，再统一汇总。 |
| **按阶段积累成果** | 一项任务不必全部结束才能贡献成果。完成一个稳定阶段，就可以交给治理整理并纳入共同版本。 |
| **保留未完成工作** | 工作暂时停下时，保存选定文件与接续说明。回来时能够找到上次的位置，暂停的任务也可以安静保留。 |
| **清楚管理迭代** | 记录新旧成果之间的关系，保留历史，并清楚区分已汇入项目的成果、准备接收的阶段与暂时保留的工作。 |
| **复用已验证的恢复方法** | 遇到工具已支持的已知问题时，先核对现场，再使用适用的恢复方法，减少重复操作。 |

这些能力由同一套本地工具提供。你可以通过 Codex 中接入的 MCP 工具使用，也可以用命令行操作；两种方式读写同一份项目状态。

## 人、AI 与工具怎样协作？

![协作结构：用户决定方向，治理聊天组织项目，专业工作台并行推进，共享持久项目记录](docs/assets/collaboration.zh-CN.svg)

**治理聊天**是项目的协调入口。它使用 Codex 的理解能力阅读已提供的工作信息、判断任务与成果的关系，再调用工具保存状态、整理交付和更新工作区。

**专业聊天**专注自己的实际工作。一个聊天可以连续处理相关子任务；需要并行时，再增加独立工作区。专业角色和数量由你的项目决定。

**AGCT 工具**把任务、文件、版本与操作结果保存下来，并在执行更新前核对目标和条件。AI 负责理解，工具负责可重复的记录与执行，人保留方向、重要取舍和最终业务决定。

这种分工让协作有一份共同依据，也让每个工作台可以保留自己的工作节奏。

## 从开始工作到继续推进

![工作流程：推进任务、保存进度、整理阶段成果、汇入项目、更新工作区、继续工作](docs/assets/governance-flow.zh-CN.svg)

例如，一个产品项目可以让三个工作台分别负责软件、实验和文档。软件完成了一个可用模块，实验还在准备，文档已经形成初稿。治理可以先接收软件的稳定成果，同时记录实验与文档的当前位置。它们不必等整个项目一起完成。

之后软件又迭代出新版本，治理会依据已声明的任务与版本关系整理成果，保留必要历史。需要采用共同进度的工作区，会先核对并保全支持范围内的本地工作；遇到冲突，则说明具体冲突，让相关工作区先处理。

这里的“接收”，指把阶段成果整理进项目。是否达到了产品目标、能否对外交付，仍由你和相应负责人判断。

## 长期记忆保存的是什么？

AGCT 将项目记忆放在聊天之外，保存在你的本地项目中。它记录的是**接续工作真正需要的信息**：

| 项目记录 | 日后可以回答的问题 |
|---|---|
| 任务状态与关键决定 | 这件事推进到哪里？为什么这样安排？ |
| 已保存的工作与下一步 | 上次停在哪里？接下来应该做什么？ |
| 阶段成果与版本关系 | 哪一份已经汇入项目？它从哪个阶段演进而来？ |
| 文件引用与成果位置 | 材料放在哪里？是否需要另行保存？ |
| 操作结果与适用经验 | 哪些已经执行？遇到同类问题可以参考什么方法？ |

你不必把每份大文件都塞进 Git。工具可以记录材料位置，方便查找和安排备份；文件的实际复制与备份仍按你的存储方式完成。需要远端保存项目成果和选定记录时，可以按手册配置私有 Git 仓库。

这些信息由你或治理聊天明确记录，未记录的对话决定不会自动成为项目记忆。它来自你接入的任务和工作材料，不会自动收集全部聊天，也不会替你保存编辑器里尚未落盘的内容。

## 接入已有项目，或从新项目开始

**已有工作可以延续。** 在原聊天中整理当前任务、成果、重要背景与未完成工作，交给治理完成接入，再把接续说明带回原聊天。你可以继续使用合适的原窗口，不必把项目重新做一遍。

**需要并行时再增加工作台。** 一个工作台对应清楚的任务范围；多个工作台通过独立目录和 Git 工作树分别推进。若几个旧聊天一直共用同一个目录，先保留一个主要写入者，其余需要并行的职责按手册迁入独立工作区。

## 三步开始

1. **准备一个项目。** [下载产品包](https://github.com/bryan123466/agent-co-governance-toolkit/releases)，按[操作手册](docs/zh-CN/windows-example.md#choose)建立项目目录。一个目录对应一个实际项目。
2. **建立治理聊天。** 选择手册指定的目录，粘贴[安装提示词](docs/zh-CN/windows-example.md#install)，填写 **【项目名称】**和 **【一句话介绍】**。
3. **接入你的工作。** [继续已有聊天](docs/zh-CN/windows-example.md#existing)，或[新增专业工作台](docs/zh-CN/windows-example.md#agents)，填写 **【每个工作台负责的实际内容】**，然后开始推进。

完整操作手册提供目录示例、可复制的提示词、MCP 接入和自动化设置。按步骤操作即可，不需要先阅读内核源码或运行开发测试。

## 从本地协作逐步扩展

- **定时整理项目。** 在 Codex 等宿主中配置定时任务，让治理聊天按计划检查已接入的工作、汇总变化和处理符合条件的更新。调度设置由宿主提供。
- **使用私有 Git 保存成果。** 将选定成果与项目记录推送到自己的远端仓库，便于追溯和恢复。远端同步需要单独配置，并按你的授权执行。
- **把不同任务分配到不同电脑。** 手册提供独立任务分支、单一集成电脑的建议流程。该流程尚未完成真实双电脑端到端验证，适合在本地流程稳定后评估采用。

## 技术与使用方式

AGCT 使用 **Python 3.11+ 与 Git**，由你现有的 **Codex** 提供 AI 能力。它包含本地执行内核、CLI、MCP 接口和四类项目技能：安装接入、任务交付、治理接收、经验恢复。工具运行时使用 Python 标准库，不需要另建模型服务。

每个项目使用一份本地治理状态和一个接收共同成果的基线。它适合让任务分开推进、成果有序汇总；同一工作区的并行写入与更新仍需协调。恢复功能覆盖已实现并经过验证的方法，不能保证自动解决所有未知故障。更多实现细节见[架构说明](docs/zh-CN/architecture.md)与[使用范围](docs/RELEASE_BOUNDARIES.md)。
